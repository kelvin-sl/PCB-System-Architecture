# 實體位置、對接與板框

## 固定共同位置基準

多份預覽或任務共用 placement 時，保存不可覆寫的版本快照；修改另立版本並列差異。板框、腳本及預覽引用同一快照 ID 與來源 hash。最新檔名、畫面方向及相同中心點不足以證明版本一致。

最小輸入契約：

| 欄位 | 必要內容 |
|---|---|
| 來源 | 原廠圖／DXF、實際板檔／封裝版本、時間及 hash；未知身份保留未知 |
| 座標 | 各來源單位、精度、原點、軸方向、頂／底視、接合面 |
| 變換 | 平移、旋轉、鏡射的順序與正反算公式；顯示與實際板座標分開 |
| 接頭 | 模組與母板 ref/pin 對照、Pin 1、腳號遞增方向、電氣／機械 pad 分類 |
| 實際放置 | footprint origin、side、rotation、mirror 與逐 pin 座標 |
| 固定條件 | 哪些元件／出線保留、可移動整組、Keepin／機構限制與待確認項 |

「向下」需對應明確數值位移，不能自行取正號或負號。用已知錨點、非對稱腳號或方向標記檢查變換；對稱外框無法排除放反。已知旋轉仍須核對實際對接視角，底視圖不等於自動多加一次鏡射。

## 從 pad 中心換算 footprint origin

DXF 電氣 pad 包絡中心、所有 pad 中心、symbol bbox 中心及 footprint origin 可能不同。先依腳號分類機械 pad，不用物件總數判斷電氣腳數衝突。

有可靠的當前 library 局部 pin 資料時直接使用。缺少時，可提出在備份／副本上暫放代表性封裝、匯出所有 pin 局部座標後回復的校正方案。這不是唯讀；保存事前不變項並驗證回復，不以 rollback 回傳值代替。

令局部電氣中心偏移為 `c`、核准的板面／旋轉變換為 `T`、目標中心為 `p`，則 `origin = p - T(c)`。每個 pin 的預期板座標為 `origin + T(local_pin)`。這是計算關係，實際 rotation／mirror 語意依 CAD 版本與封裝驗證。

先列 ref、origin、side、rotation、Pin 1 及逐腳預期座標，再交付 apply。執行後核對所有目標 pin 與未變元件，不只檢查中心或第一個 pin。公差需說明來自匯出精度、製造或機構需求；小數值差異不能自行宣告可接受。

## 板框與 Keepin

從當前設計取得 Outline／Design Outline、Package Keepin、Route Keepin 的實際物件、層及幾何；引用存在但匯出未走訪到，應標為缺資料。API 回傳 nil、沒有物件及沒有匯出欄位要分開解讀。

規劃列出舊／新邊界、單位、來源 placement 版本、設計 extents、封閉性及修改範圍。一般內縮值須有設計或製造依據；板邊連接器、cage、固定孔、工具及插接空間可需局部例外。核心板投影不自動構成全面禁止佈線區，底面元件與堆疊高度要另外判斷。

- Package Keepin：採適當的 placed instance 放置／裝配邊界，不只看 pin 中心或含文字的整個 symbol bbox。
- Route Keepin：需要 trace 寬度、pad／via 外形與 shape。先區分 definition-local 和 board/global 座標再統計越界。
- 2D 包絡重疊是空間篩查；同面放置邊界、三維干涉與正式 DRC 分別報告。

各層可接受的物件類型依工具版本查證；不要把填滿銅形狀直接當作所有邊界的通用實作。修改後讀回四類邊界與未變項，儲存狀態另外記錄。邊界存在但看不見時，再查 visibility／layer／zoom，不先重建重複物件。

任何接頭或整組位置更新後，重新核對受影響的板框、Keepin、障礙與出線。既有板框讀回通過，不表示容納後續新位置。
